Descripción detallada

El test falló durante el flujo de ingreso al módulo 'Screener' en el ambiente de producción Brasil. Al intentar ejecutar el paso 4 para validar la visibilidad de los filtros (acordeones), Cypress agotó el timeout de 90000ms sin encontrar el elemento 'button.accordion-button'. La captura de pantalla muestra que la aplicación cargó correctamente pero renderizó una página promocional de planes ('Aumente seu arsenal de datos') en lugar de la herramienta interactiva, lo que explica la ausencia de los selectores esperados.

Posibles causas

ALTA
Falta de permisos de suscripción
La captura de pantalla muestra explícitamente el mensaje 'Ver planos de assinatura' y una imagen estática del screener, indicando que el usuario actual tiene un acceso restringido (Free/Basic) que no renderiza los componentes funcionales del módulo.
MEDIA
Cambio en la lógica de acceso del módulo
Un deploy reciente podría haber modificado los requisitos de acceso para el tenant de Brasil, bloqueando al usuario de automatización que anteriormente tenía acceso.
BAJA
Fallo en la carga de perfil de usuario
Aunque el HAR no reporta errores 4xx/5xx, una respuesta lenta o incompleta de la API de permisos podría haber disparado el estado 'unauthorized' por defecto en el frontend.

Pasos de Troubleshooting

1 Verificar manualmente el acceso al Screener en https://bonds.mercapabbaco.com.br/bond-screener/ usando las credenciales de automatización.
2 Validar en el panel de administración o base de datos que el usuario de test tenga asignado un plan 'Avançado' o 'Expert'.
3 Ejecutar el test localmente apuntando a producción: TARGET_ENV=production TARGET_CLIENT=brasil MODE=only SPEC=smoke/screener npm run test
4 Revisar el HAR para confirmar si el endpoint de perfil/permisos devuelve los claims correctos para el módulo screener.
5 Si el acceso es correcto, verificar si hubo un cambio de clase CSS en los componentes de acordeón de la librería UI.
