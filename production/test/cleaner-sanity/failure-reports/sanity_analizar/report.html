Timeout 90s en Analizar AL30: placeholders (skeleton loaders) persistentes en pestaña de simulación.

Descripción detallada

El test falló durante el flujo de 'Simular inversión de la especie AL30' al agotar el timeout de 90s esperando que desaparecieran los elementos de carga. Aunque la captura de pantalla muestra que los datos (TIR, TNA, Cashflow) ya están renderizados en la UI, Cypress detectó 46 elementos 'span.placeholder-glow' aún presentes en el DOM. El análisis del HAR confirma que las peticiones críticas de datos (/metrics y /bond-payment-forecast) finalizaron exitosamente en menos de 1.2s mucho antes del timeout.

Posibles causas

ALTA
Bug de estado en componente Frontend
La UI muestra los valores calculados, pero el DOM retiene los elementos .placeholder-glow. Esto indica que la condición de renderizado para ocultar el estado de carga no se disparó correctamente para todos los nodos.
MEDIA
Elementos de carga ocultos pero existentes
Los placeholders podrían estar presentes en el DOM con opacidad 0 o fuera de vista, pero el comando de Cypress 'not.exist' falla porque el elemento sigue técnicamente en el árbol de nodos.
BAJA
Error de JS en el renderizado
Un error de JavaScript no capturado durante el mapeo de los datos del cashflow podría haber interrumpido el ciclo de vida del componente, dejando la UI en un estado híbrido.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=sanity_analizar npm run test
2 Acceder manualmente a la URL de análisis de AL30 y realizar una simulación para observar el comportamiento de los skeletons.
3 Inspeccionar el DOM mediante DevTools tras la carga para identificar la ubicación exacta de los 46 'span.placeholder-glow' residuales.
4 Verificar la consola del navegador (logs) en busca de errores de React/Angular que ocurran justo después de que /bond-payment-forecast responda.
5 Validar si el problema es específico del browser Firefox comparando resultados con Chrome.
