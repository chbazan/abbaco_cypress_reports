Timeout 90s buscando #select-row-all en Portafolio — La tabla de especies no se renderizó tras intentar editar.

Descripción detallada

El test falló durante el flujo de eliminación de especies. Tras marcarse como exitoso el paso 'Editar el portafolio', Cypress agotó el timeout de 90s esperando el elemento '#select-row-all' (checkbox de selección masiva). La captura de pantalla y el DOM del fallo confirman que la aplicación permaneció en la vista de lista de portafolios (/security-position) en lugar de navegar al detalle del portafolio donde reside la tabla.

Posibles causas

ALTA
Fallo en la interacción con el dropdown de acciones
El log indica que el paso de edición terminó, pero la UI no cambió. Es probable que el click en 'Editar' dentro del dropdown no se haya ejecutado efectivamente o no haya disparado el evento de ruteo.
BAJA
Regresión en el componente de tabla
Si la navegación ocurrió pero el DOM no muestra la tabla ni spinners, podría haber un error de JS impidiendo el renderizado del componente de especies.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=performance/portafolio.js npm run test
2 Verificar manualmente en producción si el botón 'Editar' del portafolio 'Portafolio Cypress Modificado' navega correctamente.
3 Revisar el video del test para confirmar si el menú dropdown llegó a abrirse y si se visualizó el click en 'Editar'.
4 Insertar un cy.url().should('include', '/edit') o similar antes de buscar el selector de la tabla para asegurar la navegación.
5 Verificar logs de consola en el navegador durante la ejecución para descartar errores de JS al momento del ruteo.
