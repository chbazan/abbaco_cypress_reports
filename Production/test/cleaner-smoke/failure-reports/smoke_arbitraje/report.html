Descripción detallada

El flujo 'Arbitraje > Carga las especies...' falló al intentar interactuar con el primer input de búsqueda de bonos. La acción addEspecies en arbitrajePage.js no encontró el elemento #first-security input.form-control tras agotar los 90s de reintento. La captura de pantalla muestra que la aplicación renderizó una pantalla promocional ('Aumente seu arsenal...') y un botón de 'Ver planos de assinatura', indicando que el usuario no tiene acceso al módulo. El HAR confirma un error 403 Forbidden en el endpoint de token de Auth0, lo que explica la falta de permisos.

Posibles causas

ALTA
Error de autorización 403 en Auth0
El HAR registra un fallo crítico: POST https://mercap-brasil.us.auth0.com/oauth/token devolviendo 403 Forbidden, lo que impide obtener los claims necesarios para habilitar el módulo.
MEDIA
Configuración de API errónea (Staging en Prod)
Se observan múltiples errores 503 constantes hacia pd.staging.mercap.com.ar a pesar de estar en ambiente de producción, lo que sugiere una fuga de configuración de staging.
MEDIA
Cambio en lógica de acceso/Paywall
La UI muestra explícitamente 'Disponível em: Plano Expert'. Si el usuario de QA no fue actualizado a este plan, el test fallará sistemáticamente al no encontrar los inputs.

Pasos de Troubleshooting

1 Verificar acceso manual: Loguearse en bonds.mercapabbaco.com.br con el usuario de test y navegar a Arbitraje para confirmar el bloqueo.
2 Ejecutar spec específico localmente: TARGET_ENV=production TARGET_CLIENT=brasil SPEC=smoke_arbitraje npm run test
3 Revisar logs de Auth0 para el error 403 específico en el tenant de Brasil.
4 Validar en el código de la app por qué se realizan peticiones a pd.staging.mercap.com.ar en producción.
5 Confirmar con el equipo de producto si el módulo de Arbitraje requiere ahora permisos especiales no configurados en el usuario de QA.
