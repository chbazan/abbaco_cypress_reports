Descripción detallada

El test ejecutaba el flujo de ingreso a la curva de bonos soberanos de Brasil y validación de su cuadro de bonos. El fallo ocurrió en el paso 'clickTab' al intentar localizar un elemento 'button.filter-button' con el texto exacto 'Todas'. La evidencia muestra que la página cargó correctamente el gráfico y la tabla de bonos (confirmado por 0 fallos de red), pero el selector o el texto del filtro no coinciden con lo renderizado en la UI.

Posibles causas

ALTA
Cambio en etiquetas de UI (Traducción/Texto)
El test busca exactamente '/^Todas$/i'. Si el botón ahora dice 'Todos', 'Ver todos' o cambió a minúsculas, la regex fallará tras 90s.
MEDIA
Selector CSS obsoleto
La clase '.filter-button' podría haber sido reemplazada por una clase de componente genérica o de librería de UI (ej: .btn-primary).
BAJA
Elemento condicional no renderizado
El filtro 'Todas' podría aparecer solo si existen múltiples categorías de bonos que no están presentes en la curva de Brasil seleccionada.

Pasos de Troubleshooting

1 Reproducir localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=smoke/curvas_smoke.js npm run test
2 Inspeccionar el DOM en la ruta de la curva de Brasil para verificar el texto y clase del botón de filtrado.
3 Verificar si el error persiste en otros navegadores (Chrome/Edge) para descartar problemas de renderizado en Firefox.
4 Actualizar el selector en 'cypress/support/pages/curvasPage.js' línea 10 si hubo un cambio de diseño.

Descripción detallada

El test intentaba agregar un escenario de sensibilidad y verificar el feedback de éxito. El fallo ocurrió al esperar la visibilidad del elemento con clase '.text-success' después de la acción de carga. La captura de pantalla muestra el módulo de Sensibilidad sin el escenario nuevo en la tabla, lo que indica que la acción de 'Agregar escenario' no se completó o no generó la respuesta visual esperada.

Posibles causas

ALTA
Interacción bloqueada o fallida
El clic en 'Agregar escenario' pudo no haberse ejecutado si el botón estaba deshabilitado por falta de datos obligatorios o bloqueado por un overlay invisible.
MEDIA
Cambio de clase CSS de feedback
La aplicación podría estar usando una clase distinta a '.text-success' para indicar éxito (ej: un toast de notificación o una clase de Tailwind).
BAJA
Latencia en procesamiento de datos
Aunque el HAR no muestra errores, la lógica de negocio en el frontend podría haber tardado más de 90s en procesar la adición del escenario.

Pasos de Troubleshooting

1 Ejecutar con interfaz gráfica: TARGET_ENV=production TARGET_CLIENT=argentina npm run cy:open y observar el flujo en Sensibilidad.
2 Verificar si el botón 'Agregar escenario' requiere campos adicionales que no fueron completados por el test.
3 Revisar la consola del navegador en la captura/video para identificar errores de JS (Uncaught TypeError, etc.).
