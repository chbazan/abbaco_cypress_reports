Fallo de red en Sensibilidad: banner 'Network Error' impide aparición de .text-success tras agregar escenario.

Descripción detallada

El test 'Agregar un escenario...' falló al no encontrar el elemento '.text-success' tras 60 segundos de reintentos. La captura de pantalla revela un banner de error crítico en la UI ('Oh no! Algo salió mal Network Error') que bloqueó la actualización de la tabla de sensibilidad. Aunque el log de Cypress muestra peticiones exitosas (200/304), la aplicación detectó un fallo de red que impidió completar el flujo de datos esperado.

Posibles causas

ALTA
Error de red capturado por el frontend
La UI muestra explícitamente 'Network Error'. Esto ocurre cuando una petición fetch/axios falla antes de recibir un status code (ej. timeout de conexión, error de DNS o bloqueo de CORS).
MEDIA
Timeout en el procesamiento de la sensibilidad
El cálculo de sensibilidad puede haber excedido el tiempo de espera del cliente, disparando el error de red en la interfaz antes de que Cypress agotara su propio timeout de 60s.
BAJA
Inconsistencia en la respuesta de tradable-securities
Una respuesta malformada o vacía de la API de títulos podría haber causado una excepción en el frontend que se reporta genéricamente como error de red.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=smoke/sensibilidad npm run test
2 Inspeccionar el HAR completo buscando peticiones con estado '(failed)' o latencias superiores a 30s.
3 Verificar manualmente en producción si el módulo de Sensibilidad permite agregar la especie 'AL30' sin disparar el banner de error.
4 Revisar los logs de la consola del navegador en el video/screenshot para identificar el mensaje de error exacto de la red.
5 Consultar en Datadog/Sentry por errores 5xx o excepciones de red en el endpoint de sensibilidad de api.mercapabbaco.com.
