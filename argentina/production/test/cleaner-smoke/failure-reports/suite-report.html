Timeout 90s en favoritos: icono de estrella rellena persistente tras intentar eliminar curva de favoritos

Descripción detallada

El test ejecutaba el flujo de eliminación de curvas favoritas en el módulo Curvas. Tras realizar la acción de desmarcar una favorita, Cypress esperó 90s a que el elemento <svg.tabler-icon-star-filled> desapareciera del DOM, pero este permaneció visible. La captura de pantalla muestra múltiples curvas con el estado de favorito (estrella amarilla) activo, indicando que la UI no se actualizó o la acción de click no surtió efecto.

Posibles causas

ALTA
UI no reactiva
El estado del componente no se actualizó tras el click de eliminación. Aunque el HAR no reporta errores 4xx/5xx, el elemento visual persistió durante todo el timeout de 90s.
MEDIA
Click no efectivo
El comando de click pudo haberse ejecutado sobre un elemento no interactuable o el listener no capturó la acción, impidiendo el disparo del request de eliminación.

Pasos de Troubleshooting

1 Reproducir localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=smoke/favoritos.cy.js npm run test
2 Verificar en la consola del navegador (DevTools) si existen errores de JS al hacer click en la estrella
3 Validar si el request DELETE/POST a la API de favoritos se dispara correctamente en el Network tab
4 Revisar si el selector del icono de estrella rellena ha cambiado o si hay múltiples instancias en el DOM

Descripción detallada

El test intentaba agregar un escenario en el módulo de Sensibilidad. Al ejecutar la acción, la aplicación mostró un banner de error crítico ('Oh no! Algo salió mal - Network Error'). Cypress agotó el timeout de 90s buscando el elemento '.text-success' que indica éxito, el cual nunca se renderizó debido al fallo de comunicación previo.

Posibles causas

ALTA
Error de red (Network Error)
La captura de pantalla muestra explícitamente un banner de 'Network Error'. Esto indica que una petición crítica falló, impidiendo que el flujo de 'Agregar escenario' finalizara.
MEDIA
Timeout de API Mercap
Si la API de sensibilidad tarda demasiado en procesar el nuevo escenario, el frontend puede disparar un timeout interno que resulta en el mensaje de error observado.

1 Verificar disponibilidad de la API: curl -I https://api.mercapabbaco.com/sensibilidad (o endpoint equivalente)
