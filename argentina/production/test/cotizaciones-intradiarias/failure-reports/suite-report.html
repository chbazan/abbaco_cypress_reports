Mismatch de cotización intradiaria en AL30 (Sensibilidad): Abbaco (85200) vs Pepper (85130)

Descripción detallada

El test falló al validar la igualdad entre la cotización mostrada en Abbaco y el valor de referencia de Pepper para el bono AL30. Según el screenshot y el DOM, la UI de Abbaco muestra 'Última cotización: 85.200,00', mientras que la aserción esperaba 85.130. El fallo ocurrió a los 9.7s, descartando problemas de timeout de carga y confirmando una discrepancia de datos pura.

Posibles causas

ALTA
Latencia de actualización entre proveedores de mercado
Existe un desfase natural de segundos entre diferentes proveedores de datos financieros. Una diferencia de 70 unidades (aprox. 0.08%) es consistente con un movimiento de mercado capturado por una fuente antes que por la otra.
MEDIA
Cacheo de cotizaciones en el endpoint de métricas
El request a /investments/9316/metrics podría estar devolviendo un valor cacheado en el CDN o API Gateway que no refleja el último tick de mercado procesado por Pepper.
MEDIA
Falta de tolerancia (delta) en la aserción del test
El test realiza una comparación de igualdad estricta (to equal) en un ambiente de producción volátil, lo cual es propenso a fallos por milisegundos de diferencia en las consultas.

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=cotizaciones-intradiarias_02_check-intraday-quotes-abbaco.cy.js npx cypress run
2 Verificar manualmente la cotización de AL30 en la plataforma Pepper y compararla con la UI de Abbaco en Sensibilidad
3 Inspeccionar el HAR para validar el timestamp exacto de la respuesta del endpoint /investments/9316/metrics
4 Revisar en el código del comando personalizado (commands.js:2032) si existe una lógica de reintento o tolerancia para cotizaciones volátiles
