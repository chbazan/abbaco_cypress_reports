Descripción detallada

El test 'Validar en Abbaco que la cotización intradiaria del bono AL30 sea la correcta' ejecutaba el flujo de validación de cotizaciones intradiarias. El fallo ocurrió en el paso de aserción, donde el valor '93620.0093' extraído del DOM no coincidió con el valor esperado '93710'. La evidencia del HAR muestra dos requests a 'api.mercapabbaco.com' que devolvieron un status '401 Unauthorized' con el mensaje 'No authorization provided', lo que sugiere un problema de sesión o credenciales al intentar obtener datos de mercado. La duración del test (46.7s) indica que no fue un timeout de Cypress, sino un fallo de aserción posterior a la carga de la página y la extracción del valor.

Posibles causas

ALTA
Fallo de autenticación en la API de Mercap.
El HAR muestra 'GET https://api.mercapabbaco.com/tradable-securities' y 'GET https://api.mercapabbaco.com/' con status '401' y 'Response body: No authorization provided'. Esto indica que la sesión de Auth0 o las credenciales usadas por Cypress no fueron válidas para acceder a la API.
ALTA
Sesión de Cypress/Auth0 inválida o expirada.
Los errores '401 No authorization provided' son un síntoma clásico de una sesión no establecida correctamente o un token de autenticación expirado, lo que impide que el backend de Mercap autorice las solicitudes.
MEDIA
Desincronización entre la UI y la API debido a datos no autorizados.
La UI pudo haber cargado un valor por defecto o de caché ('93620.0093'), mientras que el valor esperado para la aserción ('93710') no pudo ser obtenido de la API debido al '401', llevando al mismatch.

Pasos de Troubleshooting

1 Verificar el estado de la sesión de Auth0 en el ambiente de production/argentina abriendo Cypress en modo interactivo (TARGET_ENV=production TARGET_CLIENT=argentina npm run cy:open) y navegando manualmente a la sección de análisis del bono AL30.
2 Reproducir el spec fallido localmente (TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=cotizaciones-intradiarias_02_check-intraday-quotes-abbaco npm run test) para observar el comportamiento en tiempo real y verificar si los errores 401 se replican.
3 Inspeccionar los logs de Auth0 y los logs del backend de Mercap para el ambiente de producción en el timestamp del fallo (2026-06-17T13:15:50.113Z) en busca de errores de autenticación o autorización.
4 Probar el endpoint 'https://api.mercapabbaco.com/tradable-securities' directamente con una herramienta como Postman o curl, asegurándose de incluir un token de autorización válido para verificar su respuesta.
