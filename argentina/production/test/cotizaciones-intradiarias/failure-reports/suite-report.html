Mismatch de cotización en bono AL30 (Favoritos): se obtuvo 90450 pero se esperaba 90540

Descripción detallada

El test 'Validar la cotización intradiaria del bono AL30' falló durante la aserción del precio en la sección de Bonos Favoritos. Según el screenshot y el log de Cypress, el valor extraído de la UI fue '90450' (correspondiente a ARS 90.450,00 visible en la card), mientras que el test esperaba '90540'. La ejecución duró 11.8s, descartando problemas de timeout de carga y confirmando un fallo inmediato de lógica de datos.

Posibles causas

ALTA
Desincronización de cotización intradiaria
El precio del bono AL30 cambió en el mercado o en la API de referencia, pero la UI de Abbaco aún mostraba un valor anterior (90450 vs 90540) al momento de la captura.
MEDIA
Latencia en la actualización de la UI
La aplicación pudo haber recibido el dato actualizado pero el componente de React no se renderizó con el nuevo valor antes de que Cypress ejecutara el .invoke('.text()').
BAJA
Error en la fuente de verdad del test
Si el test obtiene el valor 'esperado' de una API externa (como Pepper), esta podría estar reportando un precio distinto al que Mercap provee a Abbaco.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=cotizaciones-intradiarias_02_check-intraday-quotes-abbaco npm run test
2 Comparar manualmente el valor en bonds.mercapabbaco.com vs una terminal de mercado (BYMA/MAE) para el bono AL30.
3 Verificar en el HAR los detalles de la respuesta del endpoint de cotizaciones de Mercap para confirmar qué valor devolvió la API.
4 Revisar si el test utiliza un margen de tolerancia (chay-near) o si requiere una igualdad estricta que no contempla la volatilidad intradiaria.
5 Consultar logs de backend para detectar demoras en la ingesta de precios desde el proveedor de datos.
