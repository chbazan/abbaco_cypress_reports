Timeout 90s: Portafolio no desaparece de la UI tras DELETE fallido (404) en API de Mercap

Descripción detallada

El test ejecutaba el flujo de eliminación de un portafolio en 'sanity/portafolio.js'. Falló en el paso de aserción final donde se esperaba que el texto 'Portafolio Cypress Modificado' desapareciera de la vista. La evidencia del HAR muestra que la petición DELETE al endpoint de portfolios falló dos veces con error 404, lo que impidió que el elemento se eliminara del sistema y, por ende, de la interfaz. Cypress agotó los 90000ms de reintento esperando un cambio de estado que nunca ocurrió.

Posibles causas

ALTA
Error 404 en DELETE /portfolios
El HAR registra explícitamente dos respuestas 404 con el mensaje '830535a7-9c10-0e00-a1dd-8afd0aee95b5 was not found' al intentar borrar el portafolio.
MEDIA
Inconsistencia de ID entre GET y DELETE
El portafolio es visible en la UI (obtenido vía GET), pero el ID utilizado para la eliminación no es reconocido por el servidor en ese momento.
BAJA
Race condition en la persistencia
El portafolio podría haber sido eliminado por una acción previa o paralela, dejando la UI desactualizada antes de que el test intentara borrarlo.

Pasos de Troubleshooting

1 Intentar reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=flows/sanity/portafolio.js npm run test
2 Verificar manualmente en la plataforma si el portafolio 'Portafolio Cypress Modificado' existe y puede ser eliminado.
3 Validar con el equipo de Backend por qué el ID 830535a7-9c10-0e00-a1dd-8afd0aee95b5 devuelve 404 en el DELETE.
4 Revisar los logs de la consola del navegador en el reporte para confirmar si el ID capturado por el test coincide con el del DOM.
5 Ejecutar el reporte de fallo local para analizar el estado previo de la lista: npm run analyze-failure -- sanity_portafolio
