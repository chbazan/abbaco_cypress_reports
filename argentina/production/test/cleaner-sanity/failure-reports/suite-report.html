Timeout 90s buscando '.ball-loader' en Curvas — El spinner de carga no fue detectado a pesar de que la UI cargó los datos

Descripción detallada

El test 'Validar que se muestren todas las curvas esperadas en la pestaña Todas' falló al intentar localizar el elemento '.ball-loader' definido en un comando personalizado (commands.js:296). Aunque el screenshot muestra que la tabla de curvas se renderizó correctamente con datos de la API, Cypress agotó los 90s esperando la aparición del spinner. Dado que el HAR indica 0 requests fallidas o lentas, la carga fue exitosa pero la sincronización del test falló.

Posibles causas

ALTA
Race condition en comando de sincronización
La carga de datos fue instantánea (confirmado por HAR con 0 lentos). El comando en commands.js:296 probablemente exige que el loader sea visible antes de continuar, pero este desapareció antes de que Cypress ejecutara el get.
MEDIA
Cambio de selector de UI
Una actualización reciente en el frontend de Abbaco podría haber reemplazado '.ball-loader' por otro componente de carga (ej. placeholder-glow), rompiendo la compatibilidad con los comandos de soporte.
BAJA
Fallo de lógica en el Page Object / Command
El test intenta validar la existencia de un loader en lugar de su ausencia, lo cual es una práctica frágil si la red responde con baja latencia.

Pasos de Troubleshooting

1 Reproducir localmente el fallo: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=curvas.cy.js npx cypress run
2 Inspeccionar la línea 296 de cypress/support/commands.js para verificar si la espera del loader es obligatoria.
3 Abrir la app manualmente en producción y verificar con DevTools si el selector '.ball-loader' sigue presente durante las transiciones de pestañas.
4 Ejecutar el test con 'npx cypress open' para observar si el spinner aparece fugazmente y Cypress lo ignora por velocidad de ejecución.
5 Verificar si el componente fue reemplazado por 'placeholder-glow' en el código fuente de la página de Curvas.
