Timeout 90s en eliminación de portafolio — API devuelve 404 en DELETE y el elemento persiste en la UI

Descripción detallada

El test 'Eliminar el portafolio creado' falló al intentar remover el portafolio 'Portafolio Cypress Modificado'. Cypress ejecutó una aserción esperando que el contenido desapareciera, pero el timeout de 90000ms se agotó porque el elemento permaneció visible. La evidencia de red muestra dos intentos fallidos de DELETE al endpoint de portafolios con error 404 Not Found.

Posibles causas

ALTA
ID de portafolio inexistente o incorrecto
El HAR registra un error 404 con el mensaje 'ab553f53-0111-0e00-a1f3-227d0aee95b5 was not found'. Esto indica que el test intentó eliminar un recurso que no existe en la base de datos de producción para ese ID específico.
MEDIA
Desincronización de estado entre UI y API
El portafolio es visible en la UI (confirmado por screenshot), pero la API no lo reconoce. Esto puede deberse a una carga de datos cacheados o a un error en la captura del ID durante el flujo del test.
BAJA
Eliminación duplicada o race condition
Si el portafolio se eliminó exitosamente en un reintento interno o paso previo no registrado correctamente, los llamados subsiguientes devolverían 404, pero la UI podría no haber procesado el cambio.

Pasos de Troubleshooting

1 Verificar manualmente en producción si el portafolio 'Portafolio Cypress Modificado' existe y puede ser eliminado.
2 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=sanity/portafolio.js npm run test
3 Validar en el código del test (línea 61) cómo se obtiene el ID del portafolio antes de ejecutar el DELETE.
4 Revisar logs de la API para el ID ab553f53-0111-0e00-a1f3-227d0aee95b5 para confirmar si fue creado correctamente en el paso anterior.
5 Verificar si hay errores de 'uncaught exception' previos en el video que puedan haber afectado la consistencia de la sesión.
