Descripción detallada

El test falló en el flujo inicial de 'Ingresar al home' dentro del spec de análisis. A pesar de que la URL cargó y se visualizan los 'Bonos favoritos', el comando en 'commands.js:561' no encontró el elemento '.card-body' tras 90s. La evidencia visual muestra que las secciones de 'Índices' y 'Tasas' permanecen en estado de carga (skeleton screens/placeholders), lo que sugiere que el renderizado completo de la página se detuvo o es extremadamente lento.

Posibles causas

ALTA
Timeout de Placeholder (Pattern #1)
El screenshot muestra placeholders activos en el centro de la pantalla. Si el comando de Cypress espera que estos desaparezcan o que aparezca el contenido final (.card-body) para continuar, el retraso de la API de Mercap bloquea el test.
MEDIA
Latencia de red en producción
El HAR registra requests lentos (>5s) incluso para el documento base. La duración total del test (323s) indica una congestión severa en el ambiente de producción o en la entrega de assets.
BAJA
Selector desactualizado en commands.js
Si hubo un deploy reciente que cambió la estructura de clases de los contenedores principales, el selector .card-body podría no estar presente en el nivel jerárquico esperado.

Pasos de Troubleshooting

1 Ejecutar el spec localmente apuntando a producción: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=sanity_analizar.cy.js npm run test
2 Verificar manualmente en el navegador si el Home de Abbaco Argentina carga las secciones de Índices y Tasas sin quedar en loop de carga.
3 Inspeccionar el DOM en la línea 561 de support/commands.js para identificar qué componente específico se intenta validar con .card-body.
4 Revisar logs de Datadog para los endpoints de la API de Mercap relacionados con el dashboard (indices, tasas) en el timestamp del fallo.
5 Validar si el problema persiste en otros browsers (Chrome/Edge) para descartar un problema de renderizado específico de Firefox.
