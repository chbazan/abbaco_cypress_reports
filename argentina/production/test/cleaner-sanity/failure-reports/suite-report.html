Fallo en eliminación de portafolio: el elemento persiste en UI tras error 404 en la petición DELETE.

Descripción detallada

El test 'Eliminar el portafolio creado' falló al intentar verificar que el portafolio 'Portafolio Cypress Modificado' desapareciera de la vista. Tras la acción de clic para eliminar, se registraron dos peticiones DELETE fallidas con código 404 (Not Found) para el ID del recurso. Debido a que la eliminación no fue exitosa en el backend, el elemento permaneció visible en el DOM, agotando el timeout de 60s de la aserción 'not.contain'.

Posibles causas

ALTA
ID de portafolio inexistente o incorrecto
La API devuelve explícitamente un 404 indicando que el ID no fue encontrado, lo que sugiere que el recurso ya no existe o el ID enviado en la URL es inválido.
MEDIA
Desincronización de estado entre UI y Backend
La interfaz lista un portafolio que la API ya no reconoce como activo, lo que indica una inconsistencia de datos en el ambiente de producción.
BAJA
Fallo en el manejo de errores de la UI
Si la petición DELETE falla, la aplicación no está removiendo el elemento ni notificando el error, dejando el portafolio visible aunque la acción haya fallado.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=sanity/portafolio.js npm run test
2 Verificar manualmente en la plataforma si el portafolio 'Portafolio Cypress Modificado' existe para el usuario de test.
3 Validar el ID del portafolio mediante una petición GET a /portfolios antes de ejecutar la acción de borrado.
4 Revisar logs de la API Mercap para el ID b8b6d62c-c00f-0e00-a17f-c8a20aee95b5 para confirmar su estado en la base de datos.
5 Ejecutar 'npm run analyze-failure -- sanity_portafolio' para inspeccionar el estado final del DOM y la red.
