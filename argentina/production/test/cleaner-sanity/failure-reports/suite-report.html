Descripción detallada

El test 'Validar que se muestren todas las curvas esperadas en la pestaña Todas' falló al intentar localizar el elemento '.ball-loader' durante el tiempo máximo de espera (90000ms). Según la captura de pantalla, la aplicación ya terminó de cargar y muestra la lista de curvas (.list-group a), lo que indica que el spinner de carga desapareció antes de que Cypress intentara validarlo o nunca llegó a renderizarse debido a una respuesta rápida de la API.

Posibles causas

ALTA
Respuesta de API inmediata
El HAR indica 0 requests lentas. Si la API de Mercap responde en milisegundos, el componente de carga puede no llegar a montarse o desmontarse antes de que Cypress ejecute el comando en la línea 296 de commands.js.
MEDIA
Selector de carga desactualizado
Se observa que el error ocurre en un comando de soporte. Si hubo un cambio reciente en la UI de Abbaco reemplazando '.ball-loader' por '.placeholder-glow', el test fallará por timeout buscando el selector antiguo.
MEDIA
Lógica de sincronización frágil
El test parece forzar la existencia del loader como paso previo. En ambientes de producción con datos cacheados, esto genera falsos negativos si el loader es efímero.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=sanity_curvas.cy.js npm run test
2 Inspeccionar el archivo cypress/support/commands.js en la línea 296 para identificar el comando que invoca a '.ball-loader'
3 Verificar manualmente en el navegador si el elemento '.ball-loader' sigue utilizándose en la pestaña de Curvas o si fue reemplazado
4 Revisar si el comando de espera puede modificarse para usar { optional: true } o esperar directamente al elemento final '.list-group a'
5 Validar en el HAR si la respuesta de 'yield-curves' fue servida desde caché (304) o fue extremadamente rápida (<100ms)
