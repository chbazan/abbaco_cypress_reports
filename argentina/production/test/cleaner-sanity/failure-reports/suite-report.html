Timeout 90s en placeholder de BDC28 al analizar — los skeleton loaders no desaparecieron por lentitud de API

Descripción detallada

El test ejecutaba la simulación de inversión para la especie BDC28 en el módulo Analizar. Durante el paso de validación de carga, los elementos 'span.placeholder-glow' (placeholders) permanecieron en el DOM durante los 90s del timeout configurado. El HAR revela una degradación severa en la API de Mercap, con requests a /metrics tardando ~30s, lo que impidió que la UI renderizara los datos finales.

Posibles causas

ALTA
Latencia extrema en API Mercap
Requests GET a /investments/19569/metrics y /19568/metrics registraron tiempos de 29.6s y 30.0s respectivamente, bloqueando el renderizado.
BAJA
Fallo en lógica de ocultamiento de placeholders
Si la API respondió pero el estado de React no se actualizó, el componente placeholder-glow podría quedar 'stuck' en el DOM.

Pasos de Troubleshooting

1 Verificar estado de salud de la API Mercap en producción: https://api.mercapabbaco.com/health
2 Reproducir localmente: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=sanity_analizar npm run test
3 Ejecutar curl -w "\nTime: %{time_total}s\n" https://api.mercapabbaco.com/investments/19569/metrics para medir latencia fuera de Cypress
4 Revisar logs en Datadog para el endpoint /metrics durante el timestamp del fallo

Elemento .ball-loader no encontrado en pestaña Todas — posible carga instantánea o cambio de UI

Descripción detallada

El test intentaba validar la visibilidad de las curvas en la pestaña 'Todas'. El fallo ocurre porque Cypress no encontró el elemento '.ball-loader' (spinner de carga) en 90s. La captura de pantalla muestra la lista de curvas ya renderizada, lo que sugiere que la carga fue tan rápida que el elemento desapareció antes de que Cypress iniciara la búsqueda o el selector cambió.

Posibles causas

ALTA
Carga de datos instantánea
El HAR no muestra requests lentos; si los datos estaban en caché, el loader pudo no mostrarse el tiempo suficiente para ser detectado.
MEDIA
Cambio de selector en la UI
Se pudo haber reemplazado .ball-loader por otro componente de carga (ej. skeleton) en una actualización reciente.

Pasos de Troubleshooting

1 Verificar si el selector .ball-loader sigue existiendo en el código fuente de la app
2 Reproducir localmente: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=sanity_curvas npm run test
3 Abrir Cypress en modo interactivo (cy:open) y observar si el loader llega a aparecer brevemente
4 Revisar si el test debería usar un comando de espera por desaparición en lugar de aparición
