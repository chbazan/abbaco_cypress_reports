Timeout de 60s en placeholders de BDC28 — la tabla de Cashflow no terminó de cargar por latencia en API.

Descripción detallada

El test falló durante el flujo de simulación de inversión para el bono BDC28 en el módulo Analizar. Al intentar validar que la carga finalizó, Cypress detectó que 46 elementos 'span.placeholder-glow' persistieron en el DOM más allá del timeout de 60000ms. La captura de pantalla muestra la calculadora con datos, pero la tabla de Cashflow a la derecha es la principal sospechosa de mantener el estado de carga. El HAR confirma degradación de performance con requests a /metrics tardando hasta 12.7 segundos.

Posibles causas

ALTA
Degradación de performance en API Mercap
El HAR registra requests lentos (GET /investments/5206/metrics) de hasta 12707ms, lo que sugiere que el backend está operando con latencia alta, afectando el renderizado final de la tabla de flujos.
MEDIA
Timeout de aserción insuficiente
El test tiene un retry de 60s para la desaparición del placeholder, pero la carga total de la página y sus múltiples requests de métricas superaron este umbral debido a la lentitud del ambiente.
BAJA
Error de renderizado en componente de Cashflow
Posible bug de UI donde el componente no oculta el placeholder a pesar de recibir los datos, aunque la latencia de red es una explicación más directa basada en el HAR.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=sanity_analizar.cy.js npx cypress run --browser firefox
2 Verificar manualmente la carga de la pestaña 'Simular inversión' para el bono BDC28 en producción.
3 Validar el tiempo de respuesta del endpoint de métricas mediante curl: curl -w "\nTime: %{time_total}s\n" https://api.mercapabbaco.com/investments/5203/metrics
4 Revisar en Datadog o logs de backend si hubo picos de latencia o errores 504/408 en el servicio de inversiones a las 12:57 UTC.
5 Analizar si el volumen de datos del cashflow de BDC28 es inusualmente grande, ralentizando el procesamiento en el cliente.
