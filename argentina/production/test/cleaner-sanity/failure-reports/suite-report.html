Descripción detallada

El test falló al intentar localizar el elemento '.ball-loader' durante la validación de la pestaña 'Todas' en Curvas Argentina. Según la captura de pantalla, la interfaz ya muestra la lista de 27 curvas cargadas correctamente, lo que indica que la aplicación funciona pero el test quedó bloqueado esperando un spinner. El error se origina en un comando personalizado en 'commands.js:296', sugiriendo una lógica de espera obligatoria por un estado de carga que no se manifestó o cuyo selector cambió.

Posibles causas

ALTA
Carrera de velocidad (Race Condition)
La API respondió tan rápido que el estado de carga fue efímero o inexistente, impidiendo que Cypress detectara el elemento '.ball-loader' antes de que desapareciera.
MEDIA
Cambio de selector en la UI
El componente de loading pudo haber sido reemplazado por placeholders (placeholder-glow) u otro tipo de spinner, haciendo que el selector '.ball-loader' sea obsoleto.
MEDIA
Lógica de comando custom errónea
El comando en la línea 296 de support/commands.js podría estar exigiendo la existencia del loader antes de validar su desaparición, fallando si la carga es instantánea.

Pasos de Troubleshooting

1 Reproducir el fallo localmente: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=sanity_curvas npm run test
2 Inspeccionar el archivo 'cypress/support/commands.js' en la línea 296 para verificar la lógica de espera del loader
3 Verificar manualmente en el navegador si el selector '.ball-loader' sigue existiendo durante las transiciones de carga
4 Revisar si el componente fue reemplazado por placeholders de Bootstrap (placeholder-glow) en actualizaciones recientes
5 Si la carga es instantánea, modificar el comando para que la espera del loader sea opcional o basada en la desaparición de placeholders
