Descripción detallada

El test 'Validar que se muestren todas las curvas esperadas en la pestaña Todas' falló al intentar localizar el elemento de carga '.ball-loader'. Según la captura de pantalla, la lista de curvas ya está completamente renderizada en la UI, lo que indica que el proceso de carga finalizó. El error ocurre en 'commands.js:296', sugiriendo que un comando custom de sincronización falló al esperar un loader que probablemente apareció y desapareció antes de que Cypress iniciara la validación, o cuyo selector ha cambiado.

Posibles causas

ALTA
Selector de loader desactualizado o inconsistente
El mensaje de error indica que Cypress buscó '.ball-loader' durante 90s sin éxito. Es probable que la aplicación ahora use '.placeholder-glow' u otro componente de carga, pero el comando en 'commands.js' no fue actualizado.
MEDIA
Condición de carrera (Race Condition) en la carga
Las peticiones a 'yield-curves' y 'markets' terminaron exitosamente (200 OK) muy rápido. El loader pudo haber estado presente menos tiempo del que Cypress tardó en ejecutar el comando 'get', resultando en un timeout de búsqueda de un elemento ya inexistente.

Pasos de Troubleshooting

1 Ejecutar el test localmente para observar el ciclo de vida del loader: TARGET_ENV=production TARGET_CLIENT=argentina SPEC=sanity_curvas npm run test
2 Revisar la línea 296 de 'cypress/support/commands.js' para identificar qué comando está invocando el selector '.ball-loader'
3 Inspeccionar manualmente la pestaña 'Curvas' en producción para verificar la clase CSS actual del spinner/loader durante la carga
4 Verificar si el comando de espera debería usar '.should("not.exist")' en lugar de una búsqueda de existencia si la carga es asíncrona y rápida
