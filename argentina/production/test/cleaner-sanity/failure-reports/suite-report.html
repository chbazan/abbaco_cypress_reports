Descripción detallada

El test 'Validar que se muestren todas las curvas esperadas en la pestaña Todas' falló al intentar localizar el elemento '.ball-loader'. Según el stack trace, el fallo ocurre en un comando personalizado en commands.js:554, probablemente un 'waitForLoader'. La screenshot muestra que la interfaz ya está completamente cargada con la lista de curvas visible, lo que indica que el proceso de carga finalizó antes de que Cypress intentara detectar el spinner.

Posibles causas

ALTA
Carrera crítica (Race Condition) en comando de espera
El comando en commands.js probablemente ejecuta un .get('.ball-loader').should('exist'). Si la API responde instantáneamente, el elemento nunca llega a existir en el DOM durante el ciclo de chequeo de Cypress.
MEDIA
Cambio de clase CSS en el componente de loading
Se pudo haber actualizado el componente de UI reemplazando '.ball-loader' por otro selector (como '.placeholder-glow'), haciendo que el selector viejo nunca se encuentre.
BAJA
Datos ya presentes por navegación previa
Si la sesión o la navegación previa ya había disparado la petición de curvas, al entrar a la pestaña 'Todas' el estado de Redux/SWR ya tiene los datos y no dispara el estado de 'loading'.

Pasos de Troubleshooting

1 Reproducir localmente el spec: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=sanity_curvas.cy.js npm run test
2 Inspeccionar el archivo cypress/support/commands.js en la línea 554 para verificar la lógica del selector .ball-loader
3 Verificar manualmente en el navegador si al recargar la pestaña 'Todas' aparece brevemente un spinner y qué clase CSS utiliza
4 Si el loader es intermitente, modificar el comando para que sea condicional o esperar directamente a la visibilidad de '.list-group a'
5 Revisar si hubo deploys recientes en el frontend que afecten a los componentes de feedback visual (spinners)
