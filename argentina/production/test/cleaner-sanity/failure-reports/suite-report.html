Timeout 90s en módulo Analizar (TX28) — Placeholders no desaparecen por error 503 en API bond-payment-forecast

Descripción detallada

El test falló durante el flujo de simulación de inversión para la especie TX28 en el módulo 'Analizar'. Al intentar cargar la proyección de pagos, la interfaz quedó bloqueada mostrando componentes de carga (skeleton screens/placeholders). La evidencia del HAR confirma que el endpoint de cashflow devolvió un error 503 (Service Unavailable) a los 115ms, lo que impidió el renderizado de los datos y provocó que Cypress agotara el timeout de 90000ms esperando que los elementos '.placeholder-glow' desaparecieran del DOM.

Posibles causas

ALTA
Indisponibilidad del microservicio de proyecciones
El HAR registra un status 503 en el POST a https://api.mercapabbaco.com/bond-payment-forecast/ inmediatamente después de la solicitud, indicando que el servicio no pudo procesar el cálculo del cashflow.
MEDIA
Manejo de errores de UI deficiente
El frontend de Abbaco no ocultó los placeholders ni mostró un estado de error (Empty State/Error Alert) ante el fallo 503 de la API, dejando al test en un loop de reintentos infinito.
BAJA
Problema específico con la especie TX28
Aunque el error es de infraestructura (503), podría dispararse por una configuración de datos anómala en el request body enviado para esta especie en particular.

Pasos de Troubleshooting

1 Verificar el estado de salud del microservicio en producción: curl -I https://api.mercapabbaco.com/bond-payment-forecast/
2 Reproducir el fallo localmente ejecutando: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=sanity_analizar npm run test
3 Revisar logs de backend en Datadog para el servicio 'bond-payment-forecast' filtrando por el timestamp 2026-06-15T19:23:40
4 Validar el Request Body del HAR en Postman para confirmar si el 503 es persistente para la especie TX28
5 Inspeccionar el reporte de fallo local con: npm run analyze-failure -- sanity_analizar
