Timeout 90s en placeholder de TX28 al simular inversión — API /investments devolvió 503 (Service Unavailable)

Descripción detallada

El flujo 'Simular inversión de la especie TX28' falló al intentar validar que los elementos de carga desaparecieran de la UI. La evidencia en el screenshot muestra un mensaje de 'Network Error' en un cuadro amarillo y múltiples skeleton loaders activos. El HAR confirma que el endpoint /investments/ falló con status 503 en dos intentos, lo que impidió la renderización de los resultados y mantuvo los placeholders en el DOM hasta agotar los 90s de timeout.

Posibles causas

ALTA
Indisponibilidad del microservicio de inversiones
El HAR registra dos respuestas 503 (Service Unavailable) consecutivas en menos de 100ms para el POST a /investments/.
MEDIA
Manejo de errores de UI insuficiente
Aunque la app detectó el error (mensaje 'Oops!'), los elementos 'span.placeholder-glow' no fueron removidos del DOM, causando el timeout del test.

Pasos de Troubleshooting

1 Verificar el estado de salud del microservicio de inversiones en el dashboard de infraestructura/Datadog.
2 Reproducir el fallo localmente ejecutando: TARGET_ENV=production TARGET_CLIENT=argentina MODE=only SPEC=sanity_analizar npm run test
3 Validar el endpoint manualmente con curl o Postman usando el token de sesión actual para descartar problemas de carga puntuales.
4 Revisar los logs de la API de Mercap para el timestamp 2026-04-26T11:50:00 para identificar la causa del 503.
5 Verificar si el error persiste en el ambiente de staging para descartar un problema de despliegue en producción.
